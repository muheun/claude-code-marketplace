# Gitmoji 매핑 가이드

Linear 이슈 제목에 사용할 Gitmoji 규칙입니다.

## 이슈 타입별 Gitmoji 테이블

| Gitmoji | 타입 | 설명 | 사용 시점 |
|---------|------|------|----------|
| 🐛 | bug | 버그/오류 | 기존 기능이 오작동하는 경우 |
| ✨ | feature | 새 기능 | 새로운 기능을 추가하는 경우 |
| 📝 | docs | 문서 | 문서 작성/수정이 필요한 경우 |
| ♻️ | refactor | 리팩토링 | 코드 개선 (기능 변경 없음) |
| 🎨 | design | UI/디자인 | 디자인, UI/UX 작업 |
| 🔧 | config | 설정/환경 | 설정 파일 변경, 환경 구성 |
| ⚡ | perf | 성능 | 성능 개선, 최적화 |
| ✅ | test | 테스트 | 테스트 작성/수정 |
| 🔒 | security | 보안 | 보안 취약점, 인증/권한 관련 |
| 🚀 | deploy | 배포 | CI/CD, 배포 관련 |
| 🔥 | remove | 제거 | 코드/기능 제거 |
| ⬆️ | upgrade | 업그레이드 | 의존성 버전 업데이트 |
| 🎉 | init | 초기화 | 프로젝트/모듈 초기 설정 |
| 💄 | style | 스타일 | CSS, 레이아웃 변경 |
| 🔀 | merge | 병합 | 브랜치 병합 관련 |
| 🔖 | release | 릴리스 | 버전 태그, 릴리스 |

## 선택 가이드

### 문제 유형별

**사용자 보고 버그:**
```
🐛 로그인 실패 시 에러 메시지 미표시
🐛 결제 금액 계산 오류
🐛 모바일에서 메뉴 미표시
```

**새로운 기능 요청:**
```
✨ 소셜 로그인 기능
✨ 이메일 알림 설정
✨ 대시보드 차트 추가
```

**개선/리팩토링:**
```
♻️ 인증 로직 모듈화
♻️ API 응답 구조 개선
♻️ 중복 코드 제거
```

**성능 이슈:**
```
⚡ 상품 목록 로딩 속도 개선
⚡ 검색 쿼리 최적화
⚡ 이미지 압축 적용
```

### 영역별

**Backend:**
- API 추가/수정 → ✨ 또는 🐛
- DB 스키마 변경 → ✨ 또는 ♻️
- 인증/권한 → 🔒

**Frontend:**
- 새 화면/컴포넌트 → ✨
- UI 버그 → 🐛
- 디자인 변경 → 🎨 또는 💄

**Infrastructure:**
- CI/CD 설정 → 🚀
- 환경 변수 → 🔧
- 모니터링 → 🔧

**Documentation:**
- README 작성 → 📝
- API 문서 → 📝
- 가이드 작성 → 📝

## 우선순위 규칙

이슈가 여러 타입에 해당할 때 선택 우선순위:

1. **🐛 bug** - 버그 수정이 최우선
2. **✨ feature** - 새 기능
3. **🔒 security** - 보안 이슈
4. **♻️ refactor** - 리팩토링
5. **⚡ perf** - 성능
6. **🎨 design** - 디자인
7. **📝 docs** - 문서
8. **🔧 config** - 설정
9. **✅ test** - 테스트

**예시:**
```
요청: "로그인 기능 개선하면서 성능도 높여주세요"
→ ✨ 로그인 기능 개선 (feature가 perf보다 우선)

요청: "버그 수정하고 관련 테스트도 추가해주세요"
→ 🐛 [버그 내용] (bug가 test보다 우선)
```

## 복합 이슈 처리

### 하나의 이슈로 처리
- 주요 작업 타입의 Gitmoji 선택
- Description에 부가 작업 명시

### 이슈 분리 권장 상황
- 완전히 독립적인 작업이 2개 이상
- 담당자가 다를 수 있는 경우
- 우선순위가 다른 경우

**분리 예시:**
```
원본: "로그인 버그 수정하고 회원가입 기능도 추가해주세요"

분리:
1. 🐛 로그인 실패 시 세션 유지 오류
2. ✨ 회원가입 기능 구현
```

## 참고

- 하나의 이슈에는 하나의 Gitmoji만 사용
- 명확하지 않으면 가장 중요한 작업 기준으로 선택
- 사용자에게 Gitmoji 선택 이유를 설명하지 않아도 됨
